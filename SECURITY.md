# Security Policy

## Reporting a vulnerability

If you discover a security issue, avoid publishing sensitive exploit details in a public issue. Instead, provide a concise description, affected area, reproduction steps when safe, and the potential impact through an appropriate private contact channel maintained by the project owner.

## Scope

Security reports are most useful when they include:

- the affected file, component, or workflow;
- clear steps to reproduce;
- expected versus actual behavior;
- suggested mitigations, if known.

Please do not include passwords, API keys, access tokens, or other secrets in reports or commits.
